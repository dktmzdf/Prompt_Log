# Tasks

## 1. 의존성과 토큰 실측

패키지 설치와 모델 파일 내려받기는 환경을 바꾸고 용량이 크므로, 실행 전에 사용자에게 확인한다.

- [ ] 1.1 `pyproject.toml`을 만들어 선택 의존성 `embed`(`onnxruntime`, `tokenizers`, `numpy`,
  `huggingface_hub`)와 각 목적을 적는다(design 결정 6, Open Questions). 패키지를 설치한 뒤
  `python -c "import onnxruntime, tokenizers, numpy, huggingface_hub"`가 성공하는지 확인하고, 설치된
  버전을 pyproject 주석에 기록한다. `onnxruntime`·`tokenizers`가 이 환경(Windows, Python 3.11)에
  설치되는지 design Risks의 가정을 확인한다.
- [ ] 1.2 두 모델(`BAAI/bge-m3`, `intfloat/multilingual-e5-base`)의 `tokenizer.json`만
  내려받아(모델 가중치는 받지 않는다) 같은 토크나이저인지 확인한다. 어휘 크기와, 한국어·영어·코드가
  섞인 표본 문장 20개의 토큰 수가 같은지 비교한 결과를 design.md 결정 1에 기록한다. 다르면 큰 쪽
  토큰 수로 센다는 규칙으로 design을 고친다.
- [ ] 1.3 저장소 복사본(`~/agent-prompt-logs/promptlog.db`를 임시 위치에 복사, 원본 저장소는 열지
  않는다)의 모든 턴에 대해 design 결정 2의 형식으로 만든 텍스트와 이벤트 하나하나의 토큰 수를
  재는 일회용 스크립트(커밋하지 않는다)를 돌린다. 턴 텍스트 토큰 수의 중앙값·90%·최대, 한도를 넘는
  턴 수, 단일 이벤트가 한도를 넘는 경우의 수를 design.md 결정 1·3에 기록하고 `CHUNK_MAX_TOKENS`를
  확정한다.

## 2. 스키마 버전 3과 청크

- [ ] 2.1 `store.py`의 `SCHEMA`에 `chunk`·`embedding` 표와 `ix_chunk_hash` 인덱스를 추가하고
  `SCHEMA_VERSION`을 3으로 올리고 `MIGRATIONS[2]`와 `TABLES`를 갱신한다(design 결정 4·5·12).
  `tests/test_schema_upgrade.py`의 버전 고정 단언(99행)을 `store.SCHEMA_VERSION`으로 바꾼다. 새
  저장소가 버전 3에 두 표가 있고, 버전 2 저장소(테스트에 고정한 버전 2 스키마로 만든다)가 원본 줄과
  기존 색인 행을 그대로 둔 채 버전 3으로 올라가고, 버전 1 저장소가 두 단계를 거쳐 올라가고, 실패하면
  버전 2로 남는지 테스트로 확인한다. 기존 테스트가 모두 통과한다.
- [ ] 2.2 `chunk.py`에 청크 텍스트 생성을 구현한다. `turn_event_rows()`의 행으로 design 결정 2의
  형식을 만들고, `summarize_tool()`로 도구 줄을 만들고, 세션 `cwd` 접두를 떼고, 실패만 표시한다.
  도구 출력·thinking이 텍스트에 없는지, 도구 줄이 이름·대상·실패 표시를 갖는지, `cwd` 아래 경로가 상대
  경로가 되는지, 프롬프트만 있는 턴과 본문 없는 턴을 합성 이벤트로 검증한다. 표준 라이브러리만
  쓰고 의존성 없이 테스트가 돈다.
- [ ] 2.3 분할을 구현한다. `TokenCounter`(`count`, `split_at`)를 주입받고 design 결정 3의 순서
  (이벤트 → 문단 → 토큰)로 나누며, 이어지는 청크에 프롬프트 앞 200자를 반복한다. 공백 기준의 가짜
  카운터로 다음을 테스트한다: 한도 안의 턴은 청크 하나, 이벤트 경계 분할, 단일 이벤트의 문단 분할,
  문단 하나의 토큰 분할, 모든 청크가 한도 이하(여러 합성 입력에 대한 불변식), 나뉜 청크를 이으면
  모든 이벤트 본문이 남음.
- [ ] 2.4 청크 행을 만든다. `text_hash`(SHA-256), `token_count`, `ts_start`·`ts_end`, 도구 이름 목록,
  실패 수, `turn_hash`, `profile`을 채운다. 같은 입력이면 같은 텍스트와 해시가 나오고, 청크 텍스트에
  날짜·시각이 없고, 필터 열이 맞게 채워지는지 합성 세션으로 검증한다.
- [ ] 2.5 청크 갱신을 구현한다(design 결정 4). 지문과 `profile`이 같은 턴은 건너뛰고, 다르거나 지문이
  `NULL`이면 다시 만들고, 사라진 턴의 청크는 지운다. 합성 저장소로 검증한다: 변경 없으면 어떤 행도
  다시 쓰이지 않음, 새 턴만 추가됨, 도구 결과만 붙은 턴은 청크 텍스트·해시가 같음, `NULL` 지문 턴도
  만들어짐, `profile`을 바꾸면 모두 다시 만들어짐, 재색인(`service.reindex`) 뒤에도 같은 청크가 나옴.
- [ ] 2.6 실제 토크나이저로 청크를 만드는 `TokenCounter` 구현을 추가하고(`tokenizers` 지연 임포트),
  저장소 복사본의 모든 세션에 청크 갱신을 돌려 청크 수, 토큰 수 분포, 한도 초과 청크가 0개인지를
  design.md에 기록한다. 의존성이 없는 환경에서 `--selftest`가 통과하는지도 확인한다.

## 3. 벡터 저장

- [ ] 3.1 `vectors.py`에 벡터 직렬화(float32 little-endian)와 `embedding` 표 입출력을 구현한다.
  저장하고 읽은 벡터가 같고, 저장된 벡터의 L2 노름이 1에 가깝고, `dim`이 실제 길이와 같고, 같은
  `(text_hash, model)`을 다시 저장해도 한 행이고(`INSERT OR IGNORE`), 모델이 다르면 공존함을 테스트한다.
  `numpy`가 없으면 건너뛴다.
- [ ] 3.2 벡터가 없는 청크 텍스트를 찾는 조회와 배치 임베딩 실행기(`embed_missing`)를 구현한다.
  인코더는 주입받는다. 가짜 인코더로 검증한다: 모두 있으면 인코더가 한 번도 호출되지 않음, 새 청크만
  계산됨, 같은 텍스트의 청크 둘은 한 번만 계산됨, 텍스트가 바뀐 청크는 새로 계산됨, 재색인 뒤에도
  벡터가 남고 새로 계산되는 것이 없음, 두 번째 배치에서 예외가 나도 첫 배치는 저장되어 재실행 시
  나머지만 계산됨(design 결정 9).
- [ ] 3.3 입력 한도 보호를 구현한다. 모델 자신의 토큰 수가 `max_tokens`를 넘으면 절단 없이
  `InputTooLong`을 낸다(design 결정 8). 한도 이하는 통과하고 초과는 오류가 나며 벡터가 저장되지 않는지
  가짜 카운터로 테스트한다.
- [ ] 3.4 점곱 순위를 구현한다(`vectors.py`, 비교용). 저장된 정규화 벡터 행렬과 질문 벡터의 점곱이
  코사인 유사도와 같고(합성 벡터로 직접 계산한 값과 대조), 상위 k가 올바른 순서로 나오고, 같은 턴의
  청크는 최고점 하나로 합쳐지는지 테스트한다.

## 4. 모델 실행

모델 가중치 내려받기는 용량이 크므로(`bge-m3` int8 약 568MB, `multilingual-e5-base` int8 약 278MB,
fp32 비교는 각각 약 2.3GB, 1.11GB) 사용자에게 확인한 뒤 진행한다.

- [ ] 4.1 `embed.py`에 모델 사양 표(design 결정 7)와 접두어 붙이기, 풀링(CLS·평균), L2 정규화를
  구현한다. 합성 은닉 상태로 테스트한다: CLS는 첫 토큰을 고르고, 평균은 패딩을 제외하고 평균을 내고,
  정규화 뒤 노름이 1이고, `bge-m3`는 접두어가 없고 `multilingual-e5-base`는 질문에 `query: `, 문서에
  `passage: `가 붙는다. 의존성이 없으면 건너뛴다.
- [ ] 4.2 모델 불러오기를 구현한다. 기본은 로컬 캐시에서만 읽고, 없으면 무엇이 없는지와 `--download`를
  안내하는 오류를 낸다. `--download`일 때만 모델 파일을 받는다(design 결정 10). 파일이 없을 때의 오류와
  네트워크 호출이 없음을 가짜 `huggingface_hub`로 테스트한다. 두 모델의 int8 ONNX와 토크나이저를
  내려받고(사용자 확인 후) 변환본의 입력·출력 이름을 읽어 design 결정 7의 가정(입력은
  `input_ids`·`attention_mask`, 첫 출력이 마지막 은닉 상태)을 확인해 기록한다.
- [ ] 4.3 ONNX 세션 실행과 배치 인코딩(`encode_passages`, `encode_queries`)을 구현한다. 실제
  `bge-m3` int8로 문장 쌍을 인코딩해, 의미가 같은 쌍의 코사인이 관련 없는 쌍보다 높은지 확인하고
  차원이 1024인지 확인한다. 변환본에 풀링이 포함된 `sentence_transformers_*.onnx`가 있고 출력이
  풀링된 벡터이면 직접 만든 벡터와 대조한 결과를 기록한다. 모델 파일이 없으면 건너뛰는 통합
  테스트로 둔다.
- [ ] 4.4 같은 확인을 `multilingual-e5-base` int8로 한다(차원 768, 접두어 적용, 의미 쌍 비교).
- [ ] 4.5 int8과 fp32의 영향을 잰다. 표본 청크 약 50개를 두 변형으로 인코딩해 같은 텍스트 벡터 사이의
  코사인 평균·최솟값을 두 모델 각각 design Risks에 기록한다. fp32 내려받기를 원하지 않으면 사용자와
  상의해 이 태스크를 건너뛰고 건너뛴 사실을 기록한다.

## 5. 임베딩 명령과 격리

- [ ] 5.1 `embed_cli.py`와 `scripts/embed.py`(`scripts/export.py`처럼 얇은 진입점)를 구현한다.
  `--model`, `--variant`, `--output`, `--download`, `--batch`, `--chunks-only`를 지원하고 청크 갱신 →
  벡터 없는 청크 임베딩 순서로 실행하며 배치마다 진행을 출력한다. 의존성이나 모델 파일이 없으면 무엇이
  없는지 `stderr`에 알리고 종료 코드 1을 내며 저장소가 바뀌지 않는지, 정상 실행은 0인지 가짜 인코더로
  테스트한다. 시스템 종료 코드는 `scripts/export.py`처럼 0이 아니면 실패다.
- [ ] 5.2 `--stats`를 구현한다. 청크 수, 토큰 수 분포, 모델별 벡터 수·차원, 표 크기를 출력한다. 합성
  저장소에서 출력된 값이 직접 센 값과 같은지 테스트한다.
- [ ] 5.3 훅 격리를 테스트한다. `export()`가 청크·임베딩 함수를 부르지 않고(호출하면 실패하도록
  바꿔 둔다), `onnxruntime`·`tokenizers` 임포트가 막힌 환경에서도 `export()`가 리포트와 색인을 정상으로
  만들고, `service`·`cli`·`store`를 임포트해도 `onnxruntime`이 로드되지 않는지 확인한다.
- [ ] 5.4 외부 전송 금지를 테스트한다. `socket` 연결을 막은 상태에서 가짜 인코더로 임베딩 명령 전체가
  끝까지 동작하고, `--download` 없이 모델 파일이 없는 경우에도 네트워크 시도 없이 오류로 끝나는지
  확인한다.
- [ ] 5.5 실제 저장소 복사본으로 두 모델을 각각 임베딩한다(사용자 확인 후). 각 모델의 청크 수, 차원,
  전체 소요 시간과 청크당 시간, 벡터 표 크기를 design.md 결정 9·Risks에 기록한다. 중간에 중단했다가
  다시 실행해 이어서 되는지, 두 번째 실행이 아무것도 계산하지 않는지 확인한다.

## 6. 모델 비교와 마무리

- [ ] 6.1 `scripts/eval_embeddings.py`에 질문 세트 읽기와 검증(design 결정 11의 형식)을 구현한다.
  `--list-turns`는 세션, 턴 번호, 프롬프트 앞부분을 출력해 라벨링을 돕는다. 잘못된 형식·존재하지 않는
  턴을 가리키는 정답이 오류로 드러나는지 합성 파일로 테스트한다. 질문 세트 기본 위치가 저장소 밖(리포트
  루트 아래 `eval/`)임을 확인한다.
- [ ] 6.2 recall@1·3·5·10과 MRR 계산을 구현한다. 합성 벡터와 정답으로 직접 손으로 센 값과 대조해 테스트한다:
  정답이 1위, 3위, 순위 밖일 때의 적중과 역순위, 정답이 여럿인 질문, 같은 턴의 여러 청크.
- [ ] 6.3 사용자가 질문 20~30개와 정답 턴을 `eval/questions.json`에 작성하면(작성은 사용자 몫이다, 이
  태스크는 그 전까지 멈춘다), 두 모델로 평가를 돌려 적중 개수와 비율, MRR을 design.md에 기록하고
  모델별 차이가 질문 한두 개 수준이면 우열을 가리지 않는다고 적는다. 어느 모델을 3단계에 쓸지 사용자와
  정한다.
- [ ] 6.4 전체 검증. `python -B scripts/export.py --selftest`가 기존 103건과 새 테스트가 모두
  통과하는지 확인한다. 새 의존성 없이(선택 의존성 미설치) 같은 명령을 실행해 의존성이 필요한 테스트는
  건너뛰고 나머지가 통과하는지도 확인한다. 아무 것도 설치하지 않은 상태의 `export()`와 Stop 훅
  경로의 소요 시간이 이 변경 전과 달라지지 않는지 실제 9MB 세션으로 확인한다.
- [ ] 6.5 `AGENTS.md`의 구조 목록에 새 파일(`chunk.py`, `embed.py`, `vectors.py`, `embed_cli.py`,
  `scripts/embed.py`, `scripts/eval_embeddings.py`)과 임베딩 명령을, `docs/rag-spec.md` §4 2단계에 완료
  내용과 선정한 모델·청크 규칙·측정 결과를 반영한다. 문서에 적은 경로와 명령이 실제와 일치하는지 확인한다.
