# Proposal

## Why

RAG 1단계가 끝나 원본 줄과 턴 색인이 저장소에 있다. 그러나 아직 질문으로 로그를 찾을
수 없다. 검색의 재료인 **청크**(검색 결과로 돌려줄 텍스트 조각)와 **임베딩**(청크를 숫자
벡터로 바꾼 것)이 없다. 2단계는 이 둘을 만들고, 두 임베딩 모델을 같은 질문으로 비교해
3단계 검색이 쓸 모델을 정한다([rag-spec](../../../docs/rag-spec.md) §4 2단계).

지금 데이터로 보면 청크 설계가 검색 품질을 좌우한다. 저장소의 턴 77개를 실측했다
(2026-10-06, 읽기 전용).

| 청크에 넣는 것 | 턴당 글자 수 중앙값 | 90% 지점 | 최대 |
|---|---|---|---|
| 도구 결과까지 전부 | 약 2,400 | 약 26,000 | 약 99,000 |
| 프롬프트와 답변만 | 약 1,170 | 약 4,300 | 약 12,700 |

본문의 대부분은 파일 내용이나 명령 출력인 도구 결과다. 이것을 임베딩에 넣으면 "그때 뭘
했지?" 같은 질문과 맞는 신호가 묻힌다. 또 모델의 입력 한도(multilingual-e5는 512토큰)를
넘는 청크는 뒷부분이 조용히 잘려 검색에서 앞부분만 대표하게 된다.

## What Changes

- **청크 생성.** 턴마다 프롬프트, 답변, 도구 호출 한 줄 요약으로 텍스트를 만든다. 도구
  결과 본문과 thinking은 넣지 않는다. 도구 한 줄 요약은 이미 있는 `summarize_tool()`처럼
  로그에 있는 필드에서만 꺼내므로 LLM이 필요 없고 로그가 외부로 나가지 않는다.
- **이벤트 경계 분할.** 한도를 넘는 턴은 이벤트 경계에서 나눈다. 이벤트 하나가 한도를 넘으면
  문단 경계에서, 그래도 넘으면 토큰 경계에서 나눠 어떤 청크도 한도를 넘지 않게 한다.
- **필터용 메타데이터.** 시각 구간, 세션, 사용한 도구, 실패한 도구 수를 청크의 열로 둔다.
  시각은 임베딩 텍스트에 넣지 않는다. 임베딩은 날짜를 의미로 다루지 못하므로 "지난주"는
  3단계에서 열로 거른다.
- **임베딩 저장.** 벡터는 청크가 아니라 **청크 텍스트의 해시와 모델 이름**을 키로 저장한다.
  턴 행이 export마다 지워졌다 다시 쓰여도, `--reindex`를 해도 텍스트가 같으면 벡터가
  남는다.
- **별도 임베딩 명령.** `scripts/embed.py`가 청크를 갱신하고 벡터가 없는 청크만 계산한다.
  Stop 훅은 건드리지 않는다. 임베딩 의존성이 없어도 export는 지금처럼 동작한다.
- **모델 두 개 지원.** `bge-m3`(CLS 풀링, 8192토큰)와 `multilingual-e5-base`(평균 풀링, 512토큰,
  `query: `·`passage: ` 접두어). ONNX Runtime으로 직접 실행하고 토크나이즈, 풀링, L2 정규화를
  코드에서 구현한다.
- **모델 비교 도구.** 사용자가 라벨링한 질문 세트로 두 모델의 recall@k와 MRR을 재는
  `scripts/eval_embeddings.py`. 질문 세트는 개인 대화 내용이라 저장소 밖에 둔다.
- **저장소 스키마 버전 2 → 3.** `chunk`, `embedding` 표를 추가한다. 업그레이드는 1단계의
  제자리 업그레이드 경로를 그대로 쓴다.
- **`pyproject.toml` 신설.** rag-spec §5에 따라 첫 의존성을 추가하는 이 변경에서 만든다.
  임베딩 의존성은 선택 의존성으로 두어 훅 경로가 영향받지 않게 한다.

BREAKING 변경은 없다. 기존 CLI·훅·리포트·색인 컬럼은 그대로다.

### Non-goals

- 검색 자체(코사인 유사도 검색 모듈, FTS5, RRF 병합, 시간 필터 해석). 3단계다. 이 변경의
  모델 비교는 비교용으로 필요한 최소한의 점곱 순위만 쓴다.
- Claude API 연결(`ask.py`)과 질의 시점 임베딩 자동 실행. 4단계다.
- 검색 조각 마스킹(키·토큰·경로). 3~4단계에서 정한다. 이번 청크는 도구 결과를 빼고 세션
  `cwd` 아래 경로를 상대 경로로 줄이는 데 그치며, 마스킹이 아니다.
- `bge-m3`의 sparse·multi-vector 출력. dense 벡터만 쓴다.
- 서브에이전트 기록(`subagents/*.jsonl`) 보존, 과거 로그 백필. 하지 않는다.
- 증분 색인(`add-raw-log-store` 보류 #2). 계속 보류한다.
- 사용하지 않게 된 임베딩(고아 벡터) 정리 명령.

## Capabilities

### New Capabilities

- `log-chunk`: 턴 색인에서 검색용 청크를 만든다. 청크에 들어가는 내용과 제외되는 내용,
  길이 한도와 분할 규칙, 필터용 메타데이터, 바뀐 턴만 다시 만드는 갱신을 책임진다.
- `log-embedding`: 청크 텍스트를 로컬 모델로 벡터화해 보관한다. 텍스트 해시와 모델 단위
  저장, 증분 계산, 모델별 입력 규칙, 훅과의 격리, 외부 전송 금지를 책임진다.

### Modified Capabilities

없음. 스키마 업그레이드는 기존 `log-store`의 "저장소 스키마 업그레이드" 요구사항이 이미
일반적으로 규정한다.

## Impact

**신규**

- `scripts/promptlog/chunk.py` — 청크 텍스트 생성, 분할, 청크 표 갱신
- `scripts/promptlog/embed.py` — 모델 사양, ONNX 모델 실행, 풀링, 정규화
- `scripts/promptlog/vectors.py` — 벡터 직렬화와 `embedding` 표 입출력, 점곱 순위
- `scripts/promptlog/embed_cli.py`, `scripts/embed.py` — 임베딩 명령 진입점
- `scripts/eval_embeddings.py` — 모델 비교
- `pyproject.toml`
- `tests/` — 청킹, 분할 불변식, 갱신, 벡터 입출력, 스키마 업그레이드, 훅 격리 회귀 테스트

**수정**

- `scripts/promptlog/store.py` — `SCHEMA`에 두 표 추가, `SCHEMA_VERSION` 3, `MIGRATIONS[2]`

`service.py`·`cli.py`·`hooks/`는 바꾸지 않는다.

**의존성**

선택 의존성 `embed`로 `onnxruntime`, `tokenizers`, `numpy`, `huggingface_hub`를 추가한다.
목적은 각각 모델 실행, 토큰 수 계산과 입력 만들기, 벡터 연산, 모델 파일 내려받기다.
`numpy`와 `huggingface_hub`는 현재 환경에 이미 있고 `onnxruntime`, `tokenizers`는 없다.
모델 파일은 저장소에 두지 않고 Hugging Face 캐시에 내려받는다(`bge-m3` int8 약 568MB,
`multilingual-e5-base` int8 약 278MB).

**호환성**

- 실제 저장소(`~/agent-prompt-logs/promptlog.db`)는 버전 2다. 다음 연결 때 버전 3으로
  올라가며 원본 줄과 기존 색인은 유지된다.
- 버전 3 저장소를 이전 코드로 열면 기존 "더 새로운 버전 거부"에 걸린다. export에서는
  `archive()`가 오류를 삼켜 리포트 생성은 계속된다.
