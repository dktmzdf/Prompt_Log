# Tasks

## 1. 스키마 버전 2와 업그레이드

- [x] 1.1 `SCHEMA`의 `turn`에 `content_hash TEXT`를 추가하고 `SCHEMA_VERSION`을 2로
  올린다. 새 파일로 만든 저장소가 버전 2이고 `turn`에 `content_hash` 컬럼이 있는지
  `PRAGMA table_info(turn)`로 확인하는 테스트를 추가한다. 기존 스키마 테스트가 그대로
  통과하는지 확인한다.
- [x] 1.2 design.md 결정 3대로 `MIGRATIONS`와 업그레이드 경로를 구현한다
  (`BEGIN IMMEDIATE` 안에서 버전 재확인 → 문 실행 → `user_version` 갱신, 오류 시
  `ROLLBACK`). 테스트에 버전 1 스키마 정의를 고정해 두고 그것으로 합성 저장소를 만든다.
  업그레이드 후 버전이 2이고, `raw_line`·`session`이 바이트 단위로 같고, 기존 `event`·
  `session_event`·`turn` 행이 남아 있으며, 기존 턴의 `content_hash`가 `NULL`인지 검증한다.
- [x] 1.3 업그레이드된 저장소를 다시 열어도 오류가 없고 내용이 바뀌지 않는지 검증하는
  테스트를 추가한다.
- [x] 1.4 `MIGRATIONS`에 실패하는 문을 끼워 넣는 테스트를 추가한다. 업그레이드가
  예외를 내고, 저장소가 버전 1·컬럼 없음·원래 내용 그대로 남는지 확인한다.
- [x] 1.5 버전 1 저장소를 두 연결이 동시에 여는 테스트를 추가한다. 둘 다 오류 없이
  끝나고, 최종 버전이 2이며 `content_hash` 컬럼이 하나뿐인지 확인한다.
- [x] 1.6 더 새로운 버전 저장소를 거부하는 기존 테스트에, 거부 뒤 저장소 내용과 버전이
  바뀌지 않았다는 검증을 더한다.

## 2. 턴 지문 계산

- [x] 2.1 design.md 결정 1·2대로 `write_index()`가 만든 이벤트 행 목록을 `turn_rows()`에
  넘기고, 턴마다 그 행들을 순서대로 직렬화한 SHA-256을 `content_hash`에 쓴다. 같은
  합성 세션을 두 번 색인해도 모든 턴의 지문이 같고 64자 16진 문자열인지 검증한다.
- [x] 2.2 합성 세션에 새 프롬프트와 답변 줄을 덧붙여 다시 적재한다. 기존 턴의 지문은
  그대로이고, 새 턴은 지문을 가진 채 생기는지 검증한다.
- [x] 2.3 마지막 턴의 도구 호출만 있고 결과가 없는 상태로 적재한 뒤, 도구 결과 줄을
  덧붙여 다시 적재한다. 그 턴의 지문만 바뀌는지 검증한다.
- [x] 2.4 더 이른 타임스탬프를 가져 정렬상 맨 앞으로 들어가는 행을 파일 끝에 덧붙여
  다시 적재한다. 뒤따르는 이벤트의 `seq`가 실제로 밀리는지 확인하고, 첫 프롬프트 이전 구간(턴 0)의 지문만 바뀌고, 이후 턴의 턴 번호와 지문이
  그대로인지 검증한다.
- [x] 2.5 버전 1에서 업그레이드한 저장소(지문 `NULL`)에서 해당 세션을 다시 적재하면
  지문이 채워지는지 검증한다.
- [x] 2.6 `session_event(source_id)` 인덱스를 `SCHEMA`와 `MIGRATIONS[1]`에 추가한다.
  새 저장소와 버전 1에서 올린 저장소에 인덱스가 있고, 실패한 업그레이드는 인덱스도
  남기지 않는지 스키마 테스트로 검증한다.
- [x] 2.7 design.md 결정 5대로 적재 끝에 이벤트를 공유하는 다른 세션의 턴 지문을
  `event` 표 기준으로 다시 계산한다. 재개 세션에서 공유 도구 호출에 결과가 붙으면 원래
  세션의 해당 턴 지문만 바뀌고, 어떤 순서로 적재해도 모든 턴의 지문이 `event` 표로 다시
  계산한 값과 같고, 공유하지 않는 세션은 그대로이고, 공유 조회가 인덱스를 쓰는지
  테스트로 검증한다. 재계산 호출을 빼면 이 테스트가 실패하는지도 확인한다.
- [x] 2.8 실제 재개 쌍으로 재계산 전후 적재 시간을 번갈아 재고 불변식 위반이 없는지
  확인한 뒤 design.md Risks에 기록한다.
