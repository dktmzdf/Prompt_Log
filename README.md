# prompt-log

Claude Code 세션 기록을 사람이 읽는 날짜별 리포트로 내보내는 플러그인.

산출물은 `~/claude-prompt-logs/` 아래에 쌓인다.

## 설치

```bash
claude plugin marketplace add <이 저장소 경로 또는 URL>
claude plugin install prompt-log@prompt-log
```

다음 세션부터 `Stop` 훅이 매 턴 리포트를 갱신한다.

---

## 무엇을 하는가

**로그를 새로 쌓지 않는다.** Claude Code가 이미
`~/.claude/projects/<프로젝트>/<세션ID>.jsonl`에 세션 전체를 남기고 있다 — 프롬프트 전문,
도구 호출 인자, 도구 결과(stdout·파일 diff), thinking, 턴별 토큰, 모델, 권한 거부까지.
문제는 사람이 읽을 수 없다는 것 하나였다. 25MB 한 줄에 1MB짜리 base64 이미지가 박혀 있다.

이 플러그인은 그 기록을 읽어 **날짜별 리포트**로 뽑는다. 하루치 일지처럼 쌓인다.

## 폴더 구조

```
claude-prompt-logs/
└── <프로젝트>/
    └── <YYYY-MM-DD>/                 그날 날짜
        └── <HH-MM>_<세션8자>/          그날의 첫 활동 시각
            ├── <프로젝트>-<날짜>-<세션8자>.md      요약 (사람용)
            └── <프로젝트>-<날짜>-<세션8자>.jsonl   상세 (재현·추적용)
```

예시:

```
Cluade/2026-08-09/16-55_83e45c6c/Cluade-2026-08-09-83e45c6c.md
```

경로 재료는 **세션 안에서 절대 변하지 않는 값**만 쓴다 — 첫 cwd, 시작 날짜·시각, 세션 ID.
하나라도 세션 도중 바뀌는 값을 쓰면 훅이 매 턴 도는 동안 같은 리포트가 여러 폴더에
복제된다. 실제로 그 버그를 겪었다(아래 참조).

세션이 여러 날에 걸치면 **날마다 그날 몫만** 따로 담긴다. 누적 스냅샷이 아니라 분할이라
중복이 없고, 날짜가 지나면 그 폴더는 완성되어 다시 바뀌지 않는다.

## 두 파일

### `.md` — 요약

헤더(기간·모델·토큰·건수) · 도구 사용 표 · 수정된 파일 목록 · 대화 타임라인.

타임라인은 프롬프트·답변·생각·도구 호출을 **발생 순서 그대로** 섞어 보여준다.

```markdown
### 3. 19:24:10

> 이거 최신버전으로 갱신하고 싶은데

<details><summary>생각</summary>
버전을 먼저 확인해야 한다
</details>

먼저 설치된 버전을 확인하겠습니다.

- `Bash` — 설치된 Claude Code 버전 확인
- `Read` — /Users/parkkujin/Cluade/package.json
```

도구 요약은 **생성하지 않고 로그에 있는 필드에서 꺼낸다.** `Bash`는 `description`
(실측 2,102회 중 2,079회에 이미 있음), 파일 도구는 `file_path`, Unity 도구는 `Title`.

### `.jsonl` — 상세

노이즈를 걷어낸 이벤트 스트림. UUID 없음, `seq` 번호로 순서를 표현한다.

```json
{"seq":12,"ts":"...","kind":"tool","name":"Bash","input":{...},"ok":true,"output":"..."}
```

도구 결과를 **요약하지 않고 4KB에서 절단만** 한다. 요약하면 "오류 원인 추적"이라는 이
파일의 존재 이유가 사라진다. 실측상 결과의 92%가 4KB 이하라 대부분 손실이 0이고,
에러는 출력의 앞이나 끝에 몰려 있어 가운데를 잘라도 증거가 남는다.

## 언제 도는가

`Stop` 훅이라 **응답이 끝날 때마다** 돈다(세션 종료가 아니라 턴 단위). 매번 JSONL 전체를
다시 읽고 리포트를 통째로 새로 쓴다.

증분 처리를 하지 않는 이유는 하나다 — **JSONL이 시간순이 아니다.** compact/resume 때문에
뒤쪽에 과거 레코드가 끼어든다(한 파일에서 74곳). 뒤에 붙은 줄만 읽으면 순서가 깨진다.
전체 재생성은 멱등이라, 세션이 죽든 훅이 몇 번 건너뛰든 다음 한 번이면 정확해진다.

비용은 무시할 만하다.

| 파일 | 시간 | 메모리 |
|---|---|---|
| 25MB (현재 최대) | 0.18초 | ~50MB |
| 99MB | 0.44초 | 215MB |
| 494MB | 2.24초 | 1.0GB |

훅 타임아웃 10초 기준 여유 55배. 한계는 시간이 아니라 메모리이며(파일 크기의 약 2배),
현재 규모에서는 한참 멀다.

## 훅이 어디서 오는가

`hooks/hooks.json`의 `Stop` 훅이 `${CLAUDE_PLUGIN_ROOT}` 상대경로로 `export.py`를 부른다.
이 컴퓨터 전용 경로는 저장소 어디에도 없다 — `export.py`는 `Path.home()`만 쓴다.

**단, 스킬 디렉터리(`~/.claude/skills/`)에 두면 훅이 발동하지 않는다.**
`claude plugin details`가 `Hooks (1)`로 인벤토리에는 잡지만 실제로는 돌지 않았다.
마켓플레이스로 설치하거나 `--plugin-dir`로 로드해야 발동한다(둘 다 실측 확인).
초기에는 이걸 몰라 `~/.claude/settings.json`에 절대경로 훅을 넣어 우회했다.

### 개발 중 테스트

설치 없이 이 세션에서만 로드해 확인할 수 있다.

```bash
claude --plugin-dir <저장소 경로> -p "테스트"
```

설치본은 `~/.claude/plugins/cache/`로 복사되므로, 소스를 고치면 재설치해야 반영된다.

## 수동 실행

```bash
python3 <저장소>/scripts/export.py --all       # 전체 백필
python3 <저장소>/scripts/export.py <파일.jsonl>  # 특정 세션
python3 <저장소>/scripts/export.py --selftest   # 로직 검증
```

# 작업 기록

## 판단: 로거가 아니라 리더를 만든다

출발점은 "프롬프트 로깅 훅 플러그인을 만들고 싶다"였다. 실측해 보니
**Claude Code가 이미 모든 것을 기록하고 있었다.** 반면 `UserPromptSubmit` 훅의 stdin은
`{prompt, session_id, cwd, transcript_path}` 수준이라 도구 호출·결과가 아예 안 들어온다.
훅으로 로그를 새로 쌓으면 이미 있는 것보다 **적게** 남는 중복 작업이 된다.

진짜 빈틈은 셋이었다 — 가독성, 보존(정리 주기가 지나면 삭제됨), 집계.
`claude` CLI에 export 서브커맨드도 없다(확인함). 그래서 방향을 리더로 잡았다.

## 실측으로 확정된 제약

추정으로 짰으면 조용히 깨졌을 지점들. 전부 자기검사가 지킨다.

| 제약 | 근거 |
|---|---|
| JSONL은 시간순이 아니다 | `09:32 → 03:46 → 03:41`로 튄다. 한 파일에 74곳 |
| 첨부 붙은 프롬프트는 `content`가 배열 | "문자열이면 사람"으로 거르면 한 세션에서 12개 누락 |
| 도구↔결과를 순서로 짝지으면 안 됨 | 전수 검증 결과 순차 페어링 정확도 95.75% (222건 어긋남) |
| 거부 지시는 `tool_result`에 묻힘 | 전 프로젝트 62건. 어떤 세션은 지시 4개 중 3개가 이 경로 |
| 마커 문자열만 보면 오탐 | 그 문자열이 담긴 평범한 도구 출력까지 지시로 오인 (63건 중 2건) |
| 슬래시 커맨드를 버리면 오귀속 | 직후 도구 41건이 직전 프롬프트에 잘못 붙는다 |
| 붙여넣은 이미지에는 경로가 없다 | 블록에 `{type, source}`뿐. 파일명 필드 자체가 없음 |
| 기록은 UTC | 그대로 찍으면 09:42가 00:42로 보인다 |
| 답변에 마크다운 제목이 섞임 | 2,645건 중 436건. 그대로 넣으면 리포트 구조가 깨진다 |
| 자정을 넘겨 이어진 턴이 있다 | 952턴 중 7건. 레코드를 날짜로 자르면 페어링이 깨진다 |

## 만드는 중에 잡은 결함

**필터 버그** — 첫 리포트가 "프롬프트 1개"로 나왔다. 첨부가 붙은 프롬프트는 `content`가
배열이라 필터에서 빠졌다. 실측하니 한 세션에서 12개, 어떤 세션은 유일한 프롬프트를 놓쳐
0개가 됐다.

**사용자 지시 실종** — 도구를 거부하며 남긴 말이 `tool_result` 안에 묻혀 타임라인에서
통째로 사라졌다. 전 프로젝트에 62건. 재현성이 목적인 로그에서 치명적이라 복원하도록 고쳤다.

**그 수정이 낸 오탐** — 마커 문자열로 찾았더니 조사용 `grep`의 **출력**까지 사용자 지시로
잡혔다. `toolDenialKind` + 시작 문구를 함께 요구해 걸렀다.

**빈 접기 버튼** — thinking의 17%(3,001건 중 519건)가 내용이 비어 있어, 펼칠 게 없는
`<details>`가 98개 생겼다. 답변에는 있던 가드가 thinking에만 빠져 있었다.

**`0000-00-00` 폴더** — 파일 선두의 timestamp 없는 메타 레코드가 첫 묶음을 만들면서
날짜를 정할 수 없어 엉뚱한 폴더가 생겼다.

## 검증에서 지적받아 고친 것

외부 검증에서 10건이 나왔다. 전부 코드를 정확히 읽은 지적이었다.

**훅이 아예 안 돌고 있었다** (치명) — 리포트를 매 턴 갱신한다는 전제가 깨져 있었다.
`settings.json`에 절대경로로 등록해 복구했다. 새 세션을 띄워 리포트 mtime이 세션 종료
시각과 일치하는 것으로 확인했다.

**세션 리포트가 폴더를 옮겨다녔다** (높음) — 슬러그를 **마지막** cwd에서 뽑고 있었다.
cwd가 13종류인 세션을 30%/60%/100%로 잘라 export하면 `Cluade` → `포트폴리오` → `Career`로
갈렸다. 첫 cwd로 고정해 세 번 다 같은 폴더에 떨어지는 것을 확인했다.

나머지 8건(UTC 시각, 슬래시 커맨드 오귀속, `input` 미절단, 이미지 번호, `NotebookEdit`
경로 키, 파일 권한 644, 소요 시간이 달력 간격, 첫 프롬프트 이전 도구 누락)도 모두 고쳤다.

## 내가 틀렸던 것

- **"`.md`는 이어붙일 수 없는 구조"** — 실제로 재보니 97%→100%일 때 **13줄만** 고쳐 쓴다.
  전부 헤더의 집계값이고 본문 9,146줄은 그대로다. 증분을 막는 진짜 이유는 JSONL 순서
  하나뿐이다.
- **"첫 프롬프트 이전 도구 호출은 0건이라 죽은 코드"** — 도구만 세었기 때문이다.
  실제로는 묶음 108개 중 7개(6%)에서 발생하며, 담기는 것은 **답변**이다
  (compact/resume 직후 이어지는 답변).
- **"훅 설정은 세션 시작 시 읽히므로 이 세션에서는 발동하지 않는다"** — 확인 없이 말했다.
  `settings.json` 훅은 재시작 없이 즉시 반영됐고 그때 이미 돌고 있었다.
- **`.md`에 대화를 안 넣은 이유** — 용량 때문이 아니었다. 첫 명세에서 "프롬프트 + 도구"로
  정의하며 답변이 그냥 빠졌고, 그걸 트레이드오프로 설명한 적이 없었다.

## 플러그인으로 전환

처음에는 `~/.claude/skills/prompt-log/`에 두고 `settings.json`의 절대경로 훅으로 돌렸다.
이제 마켓플레이스로 설치해 **플러그인 자체 훅**으로 돈다.

전환하며 확인한 것:

- **스킬 디렉터리에서만 훅이 안 됐다.** 임시 복사본에 표식을 남기는 훅을 넣고
  `--plugin-dir`로 실행하니 정상 발동했다. "플러그인 훅이 안 된다"가 아니라
  경로 문제였다.
- **`skills` 배치를 바꿨다.** 루트 `SKILL.md` + `"skills": ["./"]`는
  `claude plugin details`가 `Skills (0)`으로 세지 못했다.
  ponytail과 같은 `skills/<이름>/SKILL.md` 자동 발견 방식으로 옮겼다.
- `commandWindows`를 넣어 윈도우에서도 훅이 돈다.
- `settings.json`의 훅은 제거했다. 중복이라서가 아니라 **동시 쓰기 위험** 때문이다 —
  두 훅이 같은 파일을 `write_text()`로 덮어쓰면 내용이 섞일 수 있다.
